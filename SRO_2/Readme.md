# 🎓 СРО №16: Каталог мероприятий университета (АТУ)
### Дисциплина: «Языки и технология программирования» (Лекции №1–8)

1. Исследование и анализ предметной области1.1 Обзор проблемы и актуальностьВ современных университетах ежедневно проходит множество академических, культурных и спортивных мероприятий. Отсутствие единого централизованного источника информации приводит к низкой посещаемости событий и сложностям с организацией учёта участников. Разработка единого каталога мероприятий позволяет автоматизировать процесс публикации анонсов, регистрации студентов и фильтрации событий по интересам.1.2 Обзор аналоговTimepad / Eventbrite:Плюсы: Богатый функционал, встроенная продажа билетов, рассылки.Минусы: Перегруженный интерфейс, коммерческая направленность, отсутствие интеграции с внутренними базами университета.Университетский портал (LMS / Moodle):Плюсы: Встроен в академическую среду.Минусы: Неудобный интерфейс для поиска внеучебных мероприятий, сложная навигация.Telegram-каналы / Соцсети:Плюсы: Высокая охватываемость.Минусы: Отсутствие структурированного поиска, фильтрации по категориям и удобного автоматического подсчета забронированных мест.2. Формализация требований2.1 Функциональные требования (FR):FR-1: Просмотр полного списка доступных мероприятий.   FR-2: Фильтрация мероприятий по категории (например, Наука, Спорт, Культура).   FR-3: Добавление нового мероприятия (название, дата, категория, максимальное количество мест).   FR-4: Регистрация участника на мероприятие с уменьшением доступных мест.   FR-5: Валидация пользовательского ввода (проверка корректности даты, отсутствия пустых полей и лимита мест).   2.2 Нефункциональные требования (NFR):NFR-1: Время отклика программы при выполнении любой операции — не более 1 секунды.NFR-2: Понятный и удобный текстовый / текстово-графический интерфейс.   NFR-3: Надежная обработка ошибочных данных без аварийного завершения программы (Fault tolerance).   2.3 Пользовательские сценарии (Use Cases):Сценарий 1 (Регистрация на событие): Студент открывает каталог, выбирает мероприятие из списка, вводит свое имя и подтверждает регистрацию. Система уменьшает доступное количество мест на 1.   Сценарий 2 (Поиск и фильтрация): Пользователь выбирает фильтрацию по категории «Наука». Система выводит только релевантные события.   Сценарий 3 (Создание события): Организатор вводит данные нового события. Система проверяет корректность данных и добавляет новое событие в каталог.   3. Проектирование3.1 Выбор модели жизненного цикла ПОДля проекта выбрана Инкрементная модель ЖЦ (Incremental Life Cycle Model).   Обоснование: Позволяет быстро создать базовую версию (просмотр и фильтрацию) и последовательно наращивать функциональность (регистрация участников, проверка ошибок, расширенная статистика).   3.2 Структура данных (Python)Используются структуры и коллекции Python: dataclass / dict для представления объектов мероприятий и list для хранения каталога.
