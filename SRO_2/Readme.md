## 📌 Описание проекта

**Цель:** Разработка веб-ориентированного каталога университетских мероприятий для повышения вовлеченности студентов и автоматизации процесса регистрации.

* **Проблема:** Разрозненность анонсов мероприятий (соцсети, мессенджеры), отсутствие единой точки регистрации и прозрачного списка участников.
* **Целевая аудитория:** Студенты, преподаватели и организаторы мероприятий АТУ.

## 🔍 Анализ предметной области

В рамках исследования был проведен сравнительный анализ трех существующих аналогов:

| Аналог | Плюсы | Минусы | Вывод для нашего проекта |
| :--- | :--- | :--- | :--- |
| **TimePad** | Богатый функционал, аналитика | Перегруженный интерфейс, платный функционал | Взять простоту поиска и фильтров |
| **Университетский Telegram-канал** | Быстрое информирование | Сообщения теряются, нет базы данных | Реализовать удобную структуру карточек |
| **Google Forms** | Простая форма записи | Нет общего каталога и анонсов | Объединить каталог и форму в одном окне |

## ⚙️ Требования к системе

### Функциональные требования (FR):
- [x] **FR-01:** Отображение списка актуальных мероприятий университета.
- [x] **FR-02:** Фильтрация событий по категориям (Наука, Спорт, Культура, IT).
- [x] **FR-03:** Поиск мероприятий по ключевым словам в названии.
- [x] **FR-04:** Регистрация студента на мероприятие с валидацией ввода (ФИО, Email, Группа).
- [x] **FR-05:** Добавление новых событий организатором через модальную форму.

### Нефункциональные требования (NFR):
- **NFR-01 (Удобство):** Адаптивный и современный UI в стиле Glassmorphism с фоном главного корпуса АТУ.
- **NFR-02 (Надежность):** Защита от дублирования записей и ввода некорректных данных.
- **NFR-03 (Производительность):** Время отклика интерфейса < 100 мс (клиентский JavaScript).

## 🔄 Модель жизненного цикла и архитектура

В качестве модели ЖЦ выбрана **Инкрементная модель (Agile/Scrum)**:
1. **Инкремент 1:** Разработка базового HTML/CSS каркаса и фоновой анимации.
2. **Инкремент 2:** Создание структур данных и вывод карточек событий.
3. **Инкремент 3:** Реализация поиска, фильтрации и модального окна регистрации.
4. **Инкремент 4:** Валидация данных, интеграция отчета СРО и интерактивной презентации.
